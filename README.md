## 📖 Overview
As autonomous AI agents multiply across financial services, deploying them responsibly requires strict guardrails. **SENTINEL** is a high-performance, real-time governance control plane designed to enforce safety, security, and financial policies across fleets of autonomous financial agents.

While standard API Gateways enforce basic network limits, SENTINEL extends governance directly to AI-agent decisions by combining authorization, financial context, cryptographic auditability, and emergency controls.

---

## 🚧 Current MVP State (Phase 1: The Foundation)

The current working prototype demonstrates the core, high-speed infrastructure required to intercept and secure AI traffic before it hits the banking core.

**1. Polyglot Microservices Architecture**
*   **The Go (Golang) Gateway:** Designed to intercept raw API traffic and evaluate requests against Casbin RBAC policies in sub-millisecond times.
*   **The Python Worker:** Offloaded asynchronously via Redpanda (Kafka), this worker handles the heavy cryptographic processing without slowing down the hot-path.

**2. Cryptographic Hash-Chaining**
Every audit log entry is mathematically linked to the previous one via SHA-256 hashes generated by our Python worker, creating a tamper-proof, immutable ledger (Blockchain without Blockchain) directly in PostgreSQL.

**3. Visual React Dashboard & Kill Switch**
A premium React (Vite) dashboard displaying the live stream of Hash-Chained logs, featuring an "Emergency Stop" button capable of instantly freezing the entire AI fleet.

## 🚀 The Future Vision (Phase 2: Adaptive Autonomy)

To move SENTINEL from a "Rule Engine" to a true **Behavioural Immune System**, Phase 2 will implement a **3-Layer Adaptive Defense Architecture**.

*(For a deep dive into the mathematics and architecture of Phase 2, please read `SENTINEL_ARCHITECTURAL_INSIGHTS.md`)*

<details>
<summary>🧬 Layer 1 & 2: Behavioural DNA & Multi-Dimensional Anomaly Detection</summary>
Moving beyond static `ALLOW/DENY` rules, SENTINEL will utilize **Mahalanobis Distance** to evaluate anomalies across multi-dimensional space (correlating Time + Amount + Region + Action Type). We will also model agent sequences using **Markov Chains** to verify the *intent* and flow of the agent's workflow, not just the isolated API call.
</details>

<details>
<summary>📉 Layer 3: Dynamic Trust Scores (Earned Autonomy)</summary>
Agents are born with a Trust Score of 100. When Layer 2 detects mathematical anomalies, the agent's Trust Score degrades exponentially. Instead of binary blocks, an agent's capabilities dynamically shrink:
*   **Trust > 80:** Fully Autonomous.
*   **Trust 30-80:** Stripped of autonomy; routed to Human Approval Quarantine.
*   **Trust < 30:** Instant Network Severance.
</details>

<details>
<summary>🤖 Dummy Agent Testing Simulator</summary>
We will build a dedicated Python test suite that acts as a "Rogue AI". It fires hundreds of anomalous requests at the Go Gateway to prove that the trust degradation and dynamic spend caps hold up under live, unpredictable pressure.
</details>

## 🛠️ Technology Stack
| Category | Tech | Why? |
|----------|------|------|
| **API Gateway** | Go (Golang) | Max concurrency, sub-millisecond latency |
| **Security Worker** | Python (`hashlib`) | Fast cryptographic processing |
| **Policy Engine** | Casbin | Proven RBAC & ABAC authorization |
| **Event Stream** | Redpanda (Kafka) | Zero data-loss asynchronous audit logging |
| **Caching / State** | Redis | Atomic operations for spend caps |
| **Database** | PostgreSQL | Immutable ledger storage |
| **Dashboard** | React (Vite) | Premium real-time monitoring and Kill Switch |

## 🚀 Quick Start (Running the Phase 1 System)

**1. Start the Infrastructure**
```bash
docker-compose up -d
```
*(Spins up Redis, Redpanda, and PostgreSQL).*

**2. Start the Python Hash Worker**
```bash
cd python_workers
pip install -r requirements.txt
python audit_worker.py
```

**3. Start the React Dashboard**
```bash
cd dashboard
npm install
npm run dev
```
